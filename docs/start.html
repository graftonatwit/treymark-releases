Getting started

About two minutes from download to your first fixed note.

What you need

Required

  • Windows 10 or 11 (64-bit). Treymark is Windows only for now.
  • A web app you run on your own computer, served from localhost or 127.0.0.1 (for example http://localhost:3000). Any framework works.
  • A browser. Any browser works with the script tag. Firefox also has an add-on, which adds style clipping from other sites. (A Chrome extension is planned, not available yet.)
  • A coding agent that supports MCP or a shell: Claude Code, Codex, Cursor, Gemini CLI or similar. Treymark does not include an agent. Use the one you already have.

Not required

  • Node.js. Treymark ships its own runtime for the server, the agent connection and the command line.
  • An account, API key or internet connection. The internet is only used to check for updates and download them from GitHub.
  • Admin rights. The installer is per-user.

Optional

  • VS Code or Cursor for the notes panel.
  • Claude Code for auto-run, which starts it for you when notes arrive.
  • Obsidian to browse the notes folder (any Markdown editor works).
  • A git remote on GitHub to turn a note into a prefilled issue.

The whole flow at a glance

  1. Install Treymark and open it once. It sits in the system tray.
  2. Click Set up everything on the first screen. It asks for your project folder, installs the agent skills, connects Claude Code and adds the VS Code and Cursor panel. Nothing else to copy or paste.
  3. Add the one-line script tag to your app (or load the Firefox add-on: the same screen has a button that opens Firefox's add-on page and copies the folder path). Then open your app on localhost.
  4. Using Codex, Cursor or another agent? The Connect agent tab has the copy-and-paste setup for them.
  5. Press Alt+A on your page, click an element, type what should change, and send.
  6. Tell your agent "check my Treymark notes". It reads the note, changes the code and replies.
  7. Reload your page, read the reply on the pin, and reply again until it is right. Green means done.
What "Set up everything" changes. It adds a Treymark entry to your Claude Code user settings (the same as running claude mcp add treymark -s user ...), copies the two skills into ~/.claude/skills, and runs code or cursor --install-extension if those are installed. It runs only when you click it, and each step reports separately, so a missing tool is a note, not an error. Click it again any time after an update.

Steps 1 to 4 are one-time setup. After that, each change is steps 5 to 7. Keep Treymark running (the tray is fine) while you work, because your agent talks to it.

1. Install

  1. Download Treymark-Setup-<version>.exe from the latest release.
  2. Run it, accept the license, and choose where to install. No admin rights are needed.
Treymark is not code signed yet, so Windows may show "Windows protected your PC". Click More info, then Run anyway. Each release lists a SHA-256 checksum if you want to verify the download.

2. Pick your project

Open Treymark and click Choose project folder. Pick the root folder of the web app you are working on. Treymark starts its local server for that project and keeps notes in a .treymark folder inside it. Add .treymark/ to your .gitignore.

You can add several projects in the sidebar and click one to switch. One project is active at a time. Closing the window keeps Treymark running in the system tray; quit from the tray icon.

3. Add Treymark to your page

Script tag (any browser)

Add the tag from the Connect agent tab to your app during development only. It works in every browser on localhost. It usually looks like this (the port can differ if 4747 was busy):

<script src="http://127.0.0.1:4747/overlay.js"></script>

Firefox add-on (optional)

The add-on adds Treymark to every page on localhost or 127.0.0.1, so your project needs no changes, and it lets you clip styles on other sites.

  1. Open about:debugging and click This Firefox.
  2. Click Load Temporary Add-on and pick manifest.json in the Firefox add-on folder the app shows. With the default install it is:
%LOCALAPPDATA%\Programs\Treymark\resources\firefox-extension

Firefox removes temporary add-ons when it restarts, so repeat this after a restart until Treymark is listed on Firefox Add-ons.

4. Connect your agent

Open the Connect agent tab. It shows ready-to-copy setup for Claude Code, Codex, Cursor and any agent with a shell, using Treymark's built-in runtime. You do not need Node installed. One setup covers every project: your agent always works on the project selected in Treymark.

Claude Code example (the app fills in your real path):

claude mcp add treymark -s user cmd /c "...\Treymark\resources\bin\treymark.cmd" "mcp"

Run it in PowerShell or Command Prompt. In Git Bash, put MSYS_NO_PATHCONV=1 in front, or Git Bash turns /c into a folder path and the connection fails. Start a new agent session afterwards so it loads the Treymark tools.

Install the skill

In the same tab, click Install for Claude Code on Treymark (the note loop) and Treymark UI (a polish checklist for visual changes). For Codex, Cursor and others, copy the instructions into your AGENTS.md or rules file. The tab also lists recommended design skills made by others, with their license.

5. Your first note

  1. Open your app on localhost and press Alt+A (or click the note button in the bottom right).
  2. Click an element, or drag a box over an area. To draw instead, press D (or click Draw), circle or point at things, then press Enter.
  3. Type what should change and press Ctrl+Enter. A pin appears on the element.
  4. Treymark saves a screenshot of the area (with your drawing), the element's current styles and your window width, so your agent can see exactly what you mean and fix the right screen size.
  5. Tell your agent: "check my Treymark notes".
  6. Watch the pin change color. Click it to read the reply, and reply again to keep refining.

What the pin colors mean:

  • Blue, Waiting for agent: sent, not picked up yet.
  • Amber, Agent working: your agent claimed it.
  • Purple, Needs your reply: your agent has a question. Answer on the note.
  • Green, Done: changed. Reply to reopen it if it is not quite right.

Your agent gets the file and line

When you click an element on a React, Vue or Svelte app running in development, Treymark asks the page which source file (and for React and Svelte, which line) created that element, and adds it to the note. Your agent opens that file first instead of searching for it. Nothing to install in your project. It works on npm run dev, not on production builds. If the page cannot say, the note still carries the selector and your agent searches the code, as before.

Page errors come along

If the page logged a console error, threw an error or had a failed request just before you left the note, the note card shows N recent page errors attached. Click it to remove them before you send. Your agent reads them to fix what is broken, not only what looks wrong. Treymark keeps only the message, the stack and, for requests, the method, address (without the part after ?) and status. It never keeps request bodies, headers or cookies. Errors that happen in your own code are traced back to the line you wrote (through the source map your dev server already serves).

Before and after

When a note is marked done, Treymark takes a second screenshot of the same area. Open the note in the app and drag the slider to compare before and after. It needs your page to still be running at that address.

Clip styles you like, from any site

Notes are for your own page. Clips are for looks you want to remember. On any site, press Alt+Shift+C (or click the Treymark toolbar button, then press C), click an element, add a few tags and an optional note, and save. Treymark stores a screenshot of that element, its colors, fonts, spacing and shadows, and the page address (without anything after the ?).

  • Open the Styles tab in the app to browse your clips. If you set a notes folder, each clip is also saved there as a Markdown note with tags and its screenshot, in a Styles folder, so Obsidian can search them.
  • Click Use on my page on a clip and say what should look like it. Treymark sends your agent a note with the saved styles, and your agent can also read your clips and their screenshots.
  • On a site that is not localhost, click the toolbar button once and allow Treymark on that site. Firefox asks for each site separately. Use Alt+Shift+C or the toolbar button, not only Alt+A, if you want the screenshot: browsers only let the extension capture a page after you use the extension on it. Without it the clip is saved with styles but no picture.
  • Clips never leave your computer. Only the Treymark extension may add clips from other sites, and it can add them but not read your notes.

Notes in VS Code or Cursor (optional)

In Connect agent > Notes in your editor, copy the command for your editor and run it, or download treymark-vscode.vsix from the latest release and run code --install-extension treymark-vscode.vsix (use cursor for Cursor). Then click the Treymark icon in the activity bar: you see every note, click one to jump to the matching code, and reply or mark it done.

Open notes are also marked in the code itself. A dot in the gutter and a tinted line show where the element comes from (blue waiting, amber working, purple needs your reply). A red mark shows the line where a page error began. Hover a marked line to read the note, reply or mark it done. Marks follow the line numbers from when you left the note, so they can drift if you edit that file before the agent replies. Open the project folder in your editor so Treymark can find the files.

6. Hands-free (optional)

  • Batches: on a new note, click Add to batch instead of sending. Add more, then click Send N notes to agent. Your agent plans them together.
  • Watch mode: tell your agent "watch my Treymark notes". It waits for new notes and handles them as they arrive, inside the session you already have open.
  • Auto-run: in Connect agent, turn on Auto-run Claude Code for a project. Treymark then starts Claude Code by itself when you send notes. It can read and edit files and reply on notes, but cannot run commands. It uses your Claude plan, so it is off by default and limited to 30 runs a day. Output goes to .treymark/autorun.log.

7. Share and staging sites (optional)

  • GitHub issue: open a note in the app and click GitHub issue. Treymark opens a new-issue page with everything filled in and copies the screenshot so you can paste it. Nothing is posted until you click Submit on GitHub. The repository comes from your project's git remote, or Treymark asks once.
  • Teammates: click Export in the inbox to save your notes and screenshots as a .treymark file. Your teammate clicks Import, and their agent can pick the notes up. Imported notes are checked like any other input.
  • Staging sites: under Connect agent > Staging sites, add the address (for example https://staging.example.com). Open that site in Firefox with the Treymark add-on, click its toolbar icon, and allow it when Firefox asks. Treymark only runs on sites you add in both places.

8. Keep a UI second brain (optional)

Open the Notes folder tab and choose a folder, or click Create a new notes folder. From then on, every finished note is saved there as Markdown:

  • One note per change with the request, the element, the conversation and before and after screenshots.
  • A Changelog.md per project, newest first.

Your agent reads the changelog before new changes, so it follows what you liked before. It works best with Obsidian: pick your vault as the folder, then use Open in Obsidian. For agents that write notes too, see Obsidian skills.

Screenshots load your localhost page in a hidden window, so a page behind a login may show the login screen.

Troubleshooting

"Ports 4747-4756 are all busy"

Treymark uses the first free port from 4747 to 4756 and the extension and your agent find it automatically. This message means all ten are taken by other local servers. Close some of them, then click your project in the sidebar again.

The note button does not appear

Treymark only runs on localhost and 127.0.0.1 pages. Check that the extension is enabled, reload the page, and make sure Treymark is open with a project selected.

My agent says the server is not running

Open Treymark and select the project. Your agent talks to the app, so it needs to be running.

The agent does not see Treymark tools

Start a new agent session after adding the MCP setup. In Claude Code, run /mcp to check that treymark is connected.

Updates

From version 0.2.0, Treymark checks for updates every few hours. When one is ready, click Restart to update in the sidebar or the tray menu. If you have 0.1.x, download the latest installer once. After an update, load the Firefox add-on again if you use it (it is removed when Firefox restarts).

Start with Windows

Off by default. Turn on Start with Windows in the sidebar to have Treymark start in the tray when you sign in.

Uninstall

Use Windows Settings > Apps. Your notes stay in each project's .treymark folder until you delete them.
